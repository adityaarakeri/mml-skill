00The mental model (read this once)

Everything else in this runbook follows from one idea.

An MML document is an HTML file with 3D tags. In an interactive document, the <script> runs once, on a server, against a single DOM. Browsers connect over WebSocket and receive a live mirror. When the script calls setAttribute, the server diffs the DOM and pushes the change to every connected client.

A normal web page is a handout — one copy per visitor. An MML document is a whiteboard at the front of the room — one server holds the marker, everyone sees the same board. Users are told apart by event.detail.connectionId.

Consequences you will use every day

State lives in script variables on the server (and resets on reload). Browser-only APIs do not exist — no localStorage, no requestAnimationFrame. fetch, timers, and the standard DOM API all work. The clock is document.timeline.currentTime.

Prerequisites

Node.js 16+ and npm (for @mml-io/mml-cli), bash (git-bash works on Windows), and a modern browser. No accounts, no API keys.

02Your first scene in 90 seconds

Scaffold, serve, and see the multiplayer magic trick.

# 1. scaffold a project (picks up the current mml-cli version)
scripts/new-mml-project.sh ~/code/my-scene --example parkour
cd ~/code/my-scene

# 2. serve with live reload
npm run dev                   # -> http://localhost:7079

# 3. validate anytime
npx mml validate documents/scene.html

Now the test that proves the whole model: open two browser tabs at localhost:7079. Click the cube in one tab. It changes in both. That is the networked DOM working — and it is also the cheapest regression test you have.

Windows note

cmd.exe does not expand globs. mml validate documents/*.html fails with "File not found" — list files explicitly, or run from git-bash.

04The build workflow the skill enforces

Seven steps, in order. Skipping one is where bugs come from.

  1. Read the reference first. Attribute names are exact (font-color, not text-color). Guessing produces documents that validate and render nothing.
  2. Decide static vs interactive. No <script> means any static host works. A script forces a server. Do not add scripts to documents that do not need them.
  3. Scaffold with new-mml-project.sh — dev/validate scripts, documents/, assets/, README.
  4. Write the document: one <body> root, scene tags first, one script at the end, every scripted element gets an id, script wrapped in //<![CDATA[ ... //]]>.
  5. Validate: npx mml validate. The validator checks against the official schema — an unknown attribute is a real bug.
  6. Serve and look: npm run dev, then the two-tab multiplayer check.
  7. Hand over with a README — how to run, what each file is, how to deploy.

Rules of thumb that prevent the classic bugs

  • Y is up, units are meters, rotations are degrees. A default cube is centered on its position — lift it by half its height or it sits half-buried.
  • Always include an <m-light>; the CLI's client adds none, so unlit scenes render as black silhouettes.
  • Keep the scene near the origin (x/z within ±5, y 0–5); the default camera is at 0,5,10.
  • Never animate with a fast setInterval — every setAttribute is a network message to every client. Use m-attr-anim (document-time animation) or m-attr-lerp (smooths any scripted change); both cost zero ongoing messages.
  • Never write self-closing tags. <m-cube /> passes the XML validator but the HTML parser leaves it open, and everything after becomes its child.

05Bundled examples

Three complete, validated documents in assets/templates/. Scaffold any of them with --example <name>.

parkour

A timed 10-platform course: start pad, 8 ordered checkpoints, finish. Per-player personal bests, a top-5 leaderboard, anti-cheat on checkpoint order, and dual collision+click input so it works in avatar worlds and the fly-camera viewer. The whole course is one editable COURSE array.

disco-floor

A 6x6 grid of clickable tiles cycling through a palette, with a live counter and a springy reset button. Demonstrates dynamic DOM construction, coordinate-derived ids, and m-attr-lerp polish.

game-of-life

Conway's Game of Life as a wall display. The canonical grid pattern: state in a plain array, one element per live cell, only touching what changed each tick.

scene (default)

The minimal starter: a light, a cube, a label, and a click counter that reports which connection clicked — the smallest possible proof of multi-user state.

06Avatar worlds: making it playable

The CLI viewer gives you a fly camera. For a controllable character, serve your documents inside an avatar world.

mkdir world && cd world
npm init -y && npm install @mml-io/3d-web-experience
mkdir mml-documents           # put your MML documents here (auto-detected)
npx 3d-web-experience serve world.json --port 8085
// world.json
{
  "chat": true,
  "auth": { "allowAnonymous": true },
  "mmlDocuments": {
    "parkour.html": {
      "url": "ws:///mml-documents/parkour.html",
      "position": { "x": 0, "y": 0, "z": 0 }
    }
  }
}

Controls: WASD to run, Space to jump (double-jump supported), Shift to sprint, mouse to look. Every browser tab is a separate avatar and connectionId. Add --host 0.0.0.0 for LAN multiplayer.

Design for real legs

The avatar reliably clears about 0.6 m of rise per jump and 2–3 m gaps between platform centers; platforms below 1.2 m square get frustrating. A course designed for the fly camera is usually unplayable by an avatar — retune spacing when you move a scene into a world. Full numbers in references/avatar-worlds.md.

Pointer lock caveat

The avatar camera needs the Pointer Lock API. Embedded webviews (app preview panes, some iframes) often deny it — WASD works but mouse-look does not. Open the world in a real browser tab.

07Headless testing (no 3D client required)

A Networked DOM server speaks a simple JSON protocol over WebSocket. You can smoke-test game logic from a script or CI.

  1. Connect to ws://host:port/<document> with subprotocol networked-dom-v0.1.
  2. The first messages include {"type":"snapshot","snapshot":...} — the full DOM tree with nodeIds. Walk it to map element ids to nodeIds.
  3. Send events: {"type":"event","nodeId":N,"name":"click","bubbles":true,"params":{...}}. Collision events work the same way with params.position.
  4. Assert on the {"type":"attributeChange",...} diffs the server broadcasts back.

This is how "player finishes course, leaderboard updates" becomes a CI assertion. Python's stdlib is enough if no websocket library is available. Recipe details: references/avatar-worlds.md.

08Troubleshooting: the greatest hits

The full list of thirteen lives in SKILL.md. These are the ones that account for most lost hours.

SymptomCause and fix
Nothing rendersScene is off-camera, or a model URL 404s. Drop a <m-cube color="red" y="0.5"> at the origin as a sanity check; check devtools network tab for failed .glb loads.
Everything is black silhouettesNo <m-light>. The CLI client adds none (viewer.mml.io does, which is why official examples look fine without one).
Attribute silently ignoredMisspelled name. Run mml validate — an unknown attribute is a real bug, not a style nit.
Objects half undergroundPrimitives are centered on their position. Lift by half the height.
validate: "StartTag: invalid element name"A bare <, > or && in the script. Wrap it: <script>//<![CDATA[ ... //]]></script>.
validate: "Extra content at end of document"More than one top-level element. Wrap the file in one <body>.
Scene works, then everything is weirdly transformedA self-closing tag upstream swallowed the rest of the document as children. Always write explicit closing tags.
Jitter / lag with many usersToo many setAttribute calls per second. Switch to m-attr-anim/m-attr-lerp or lower the tick rate.
Ghost users accumulateMissing window disconnected handler. Clean up everything keyed by that connectionId.
Script errors invisibleThey print in the terminal running the server, not in any browser console.
Port still busy after killing the server (Windows)The npx wrapper died but the node child survived. netstat -ano | grep :7079, then taskkill -F -T -PID <pid>.

09Maintenance: keeping the skill honest

MML is a 0.x project. Any minor release can rename attributes. The skill assumes drift and checks for it.

# is upstream still what the references describe?
scripts/check-upstream.sh            # report only; exit 1 on drift
scripts/check-upstream.sh --accept   # regenerate elements.md, re-pin upstream.lock
  • upstream.lock pins the exact upstream commit and file hashes the skill was built from (currently MML 0.26.1).
  • The bundled GitHub Action re-checks every Monday and opens an issue when something moved.
  • At the start of any MML task, agents compare npm view @mml-io/mml-cli version against the lock and warn before trusting the references.
  • The drift check also re-validates every bundled template against the new CLI — catching behavioral changes (like parser rules) that no file diff would show.
If drift is detected

elements.md regenerates automatically. events.md, local-dev.md, and the SKILL.md workflow are hand-written — read the printed diffs, reconcile by hand, then rerun with --accept.
