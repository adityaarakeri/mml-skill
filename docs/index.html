00The mental model

Everything else in this runbook follows from one idea. Read it once.

An MML document is an HTML file with 3D tags. In an interactive document, the <script> runs once, on a server, against a single DOM. Browsers connect over WebSocket and receive a live mirror. When the script calls setAttribute, the server diffs the DOM and pushes the change to every connected client.

A normal web page is a handout — one copy per visitor. An MML document is a whiteboard at the front of the room: one server holds the marker, everyone sees the same board. Users are told apart by event.detail.connectionId.

Consequences you use every day

State lives in script variables on the server and resets on reload. Browser-only APIs do not exist — no localStorage, no requestAnimationFrame, no canvas. fetch, timers, and the standard DOM API all work. The clock is document.timeline.currentTime.

Prerequisites

Node.js 16+ and npm (for @mml-io/mml-cli), bash (git-bash works on Windows), and a modern browser. No accounts, no API keys.

02Your first scene in 90 seconds

Scaffold, serve, and see the multiplayer magic trick.

bashquickstart
# 1. scaffold a project (picks up the current mml-cli version)
scripts/new-mml-project.sh ~/code/my-scene --example parkour
cd ~/code/my-scene

# 2. serve with live reload
npm run dev                   # http://localhost:7079

# 3. validate anytime
npx mml validate documents/scene.html

Now the test that proves the whole model: open two browser tabs at localhost:7079. Click the cube in one tab. It changes in both. That is the networked DOM working — and it is the cheapest regression test you have.

Windows note

cmd.exe does not expand globs, so mml validate documents/*.html fails with "File not found". List the files explicitly, or run from git-bash.

04The build workflow

Seven steps, in order. Skipping one is where the bugs come from.

  1. Read the reference first. Attribute names are exact — font-color, not text-color. Guessing produces documents that validate and render nothing.
  2. Decide static vs interactive. No <script> means any static host works. A script forces a server.
  3. Scaffold with new-mml-project.sh — dev/validate scripts, documents/, assets/, README.
  4. Write the document: one <body> root, scene tags first, one script at the end, an id on every scripted element, script wrapped in //<![CDATA[ … //]]>.
  5. Validate with npx mml validate. It checks against the official schema — an unknown attribute is a real bug.
  6. Serve and look: npm run dev, then the two-tab multiplayer check.
  7. Hand over with a README — how to run it, what each file is, how to deploy.

Rules of thumb that prevent the classic bugs

  • Y is up, units are meters, rotations are degrees. A primitive is centered on its position — lift it by half its height or it sits half-buried.
  • Always include an <m-light>. The CLI client adds none, so unlit scenes render as black silhouettes.
  • Keep the scene near the origin (x/z within ±5, y 0–5); the default camera sits at 0,5,10.
  • Never animate with a fast setInterval — every setAttribute is a network message to every client. Use m-attr-anim or m-attr-lerp; both cost zero ongoing messages.
  • Never write self-closing tags. <m-cube /> passes the XML validator, but the HTML parser leaves it open and everything after becomes its child.

05Bundled examples

Complete, validated documents in assets/templates/. Scaffold any of them with --example <name>.

parkour

A timed 10-platform course: start pad, 8 ordered checkpoints, finish. Per-player bests, a top-5 leaderboard, anti-cheat on checkpoint order, and dual collision+click input so it works in avatar worlds and the fly-camera viewer. The course is one editable COURSE array.

disco-floor

A 6×6 grid of clickable tiles cycling a palette, with a live counter and a springy reset button. Demonstrates dynamic DOM construction, coordinate-derived ids, and m-attr-lerp polish.

game-of-life

Conway's Game of Life as a wall display. The canonical grid pattern: state in a plain array, one element per live cell, touching only what changed each tick.

scene (default)

The minimal starter — a light, a cube, a label, and a click counter that reports which connection clicked. The smallest possible proof of multi-user state.

06Avatar worlds

The CLI viewer gives you a fly camera. For a controllable character, serve your documents inside an avatar world.

bashworld setup
mkdir world && cd world
npm init -y && npm install @mml-io/3d-web-experience
mkdir mml-documents           # auto-detected; put your documents here
npx 3d-web-experience serve world.json --port 8085
jsonworld.json
{
  "chat": true,
  "auth": { "allowAnonymous": true },
  "mmlDocuments": {
    "parkour.html": {
      "url": "ws:///mml-documents/parkour.html",
      "position": { "x": 0, "y": 0, "z": 0 }
    }
  }
}

Controls: W A S D to run, Space to jump (double-jump supported), Shift to sprint, mouse to look. Every browser tab is a separate avatar and connectionId. Add --host 0.0.0.0 for LAN multiplayer.

Design for real legs

The avatar reliably clears about 0.6 m of rise per jump and 2–3 m gaps between platform centers; platforms under 1.2 m square get frustrating. A course designed for the fly camera is usually unplayable by an avatar — retune the spacing when you move a scene into a world. Full numbers live in references/avatar-worlds.md.

Pointer lock caveat

The avatar camera needs the Pointer Lock API. Embedded webviews (app preview panes, some iframes) often deny it — WASD works but mouse-look does not. Open the world in a real browser tab.

07Headless testing

A Networked DOM server speaks a small JSON protocol over WebSocket, so game logic can be smoke-tested from a script or CI — no 3D client required.

  1. Connect to ws://host:port/<document> with subprotocol networked-dom-v0.1.
  2. The first messages include a snapshot — the full DOM tree with nodeIds. Walk it to map element ids to node ids.
  3. Send events shaped like {"type":"event","nodeId":N,"name":"click","bubbles":true,"params":{…}}. Collision events work the same way with params.position.
  4. Assert on the attributeChange diffs the server broadcasts back.

This is how "player finishes course, leaderboard updates" becomes a CI assertion. Python's standard library is enough when no websocket package is available. The full recipe is in references/avatar-worlds.md.

08Troubleshooting

The complete list of thirteen lives in SKILL.md. These account for most lost hours.

SymptomCause and fix
Nothing rendersScene is off-camera, or a model URL 404s. Drop a red cube at the origin as a sanity check; watch the devtools network tab for failed .glb loads.
Everything is a black silhouetteNo <m-light>. The CLI client adds none — viewer.mml.io does, which is why the official examples look fine without one.
Attribute silently ignoredMisspelled name. Run mml validate; an unknown attribute is a real bug, not a style nit.
Objects half undergroundPrimitives are centered on their position. Lift by half the height.
validate: "StartTag: invalid element name"A bare <, > or && inside the script. Wrap it in the //<![CDATA[ … //]]> comment pair.
validate: "Extra content at end of document"More than one top-level element. Wrap the whole file in a single <body>.
Scene renders, then everything is oddly transformedA self-closing tag upstream swallowed the rest of the document as its children. Always write explicit closing tags.
Jitter or lag with several usersToo many setAttribute calls per second. Switch to m-attr-anim/m-attr-lerp, or lower the tick rate.
Ghost users accumulateMissing disconnected handler on window. Clean up everything keyed by that connectionId.
Script errors are invisibleThey print in the terminal running the server, not in any browser console.
Port still busy after killing the server (Windows)The npx wrapper died but the node child survived. Find it with netstat -ano, then taskkill -F -T -PID <pid>.

09Maintenance

MML is a 0.x project — any minor release can rename attributes. The skill assumes drift and checks for it.

bashdrift check
# is upstream still what the references describe?
scripts/check-upstream.sh            # report only; exit 1 on drift
scripts/check-upstream.sh --accept   # regenerate elements.md, re-pin upstream.lock
  • upstream.lock pins the exact upstream commit and file hashes the skill was built from (currently MML 0.26.1).
  • The bundled GitHub Action re-checks every Monday and opens an issue when something moved.
  • At the start of any MML task, agents compare npm view @mml-io/mml-cli version against the lock and warn before trusting the references.
  • The drift check re-validates every bundled template against the new CLI, catching behavioral changes that no file diff would show.
If drift is detected

elements.md regenerates automatically. events.md, local-dev.md, and the SKILL.md workflow are hand-written — read the printed diffs, reconcile by hand, then rerun with --accept.
